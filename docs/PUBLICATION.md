# Portable installations and publication

## Each installation owns its trust

There is no shared Protect certificate. At setup, the user selects/confirms their own console. The app reads the public certificate without sending login credentials, then stores confirmed trust in private Home Assistant app data. Native chime TLS verifies that installation's certificate and SHA-256 pin before connecting. Management HTTPS maintains its own pin for the console's management endpoint; different console ports need not use the same certificate.

The first confirmation associates the observed console with the user's chosen address; it is not independent proof of the console's identity. Replacing a confirmed certificate requires confirmation again. A legacy installation that saved only a pin can recover the public certificate only if it exactly matches that existing pin. Missing trust is never replaced with a developer certificate or a global disable-verification setting.

Virtual-device certificates and keys are generated separately on each installation and remain in HA app data. Existing adopted identities are preserved during upgrades. HA backups contain private installation state and must not be added to the source repository.

## No bundled Protect recordings

The app ships without default ringtone files, extracted firmware sounds or an automatic success recording. Its ringtone store starts empty. Protect's native connection sequence queries the chime's audio inventory and uploads missing default/custom tracks. The authoritative track number and filename come from that upload, and the bytes are cached privately in HA app data. Later ring commands select the received track; they are not a live audio stream from the camera.

If synchronization has not supplied a requested track, the app reports it unavailable rather than choosing a different recording. Speaker setup is silent. This keeps the distributed app independent of any particular user's Protect package or firmware extraction.

## Source boundary

Publish the repository with its `protect_anychime/` app folder, not a development workspace, HA backup or deployment data directory. Public source contains code, tests, documentation and public product metadata/artwork. It contains no real console certificate/pin, account credentials, LAN addresses, device identities, recordings, network leases or development verification dumps.

Test certificates are generated temporarily with synthetic `.invalid` names. Test networks and entity names are fictional fixtures. Commercial manufacturer/model names in image compatibility rules identify supported products and do not represent a user's device inventory.

Run from the repository root before preparing a release:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s protect_anychime/app -p 'test_*.py'
python3 tools/check_release.py
```

The checker rejects runtime state, private/certificate files, recordings, generated bytecode and developer-specific filesystem paths. It is an additional guard, not a replacement for reviewing the release diff and repository history. `.gitignore` and `.dockerignore` keep local artifacts out of normal source and container builds.

## Remaining publication decisions

Project code uses the root MIT license. Review third-party artwork/catalogue distribution terms documented in `protect_anychime/ASSETS.md`. The configured public repository URL is `https://github.com/bramboe/protect-anychime`; it is included in the root README, repository metadata and app information. No repository is published automatically by these changes.


Visible product name: **Protect AnyChime**. The internal app slug is `protect_anychime`. Home Assistant treats the renamed app as a separate installation; existing users must transfer their private saved state using the documented migration flow. No Protect device reset or re-adoption is needed when the original identities are retained. Installation-specific renderer aliases and per-installation bundled product-photo maps are not part of the source. Shared public catalogue entries and documented integration behavior are compatibility data, independent of any user inventory.
